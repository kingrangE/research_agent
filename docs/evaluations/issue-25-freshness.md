## 추적 의미와 입력 계약

`evaluate_freshness.py`는 JSON 파일을 받아 기사/정정/시세 버전별 단계를 집계한다. `scripts/evaluate_freshness.py`는 기존 저장·가공·API·가격 비교 경로를 호출하는 격리 재생기다. UI나 API에 영구 측정 코드를 추가하지 않는다. 입력에는 실제 원문·시세 대신 합성 데이터만 코드로 정의했다.

| 필드 | 의미 |
| --- | --- |
| `kind`, `id`, `version`, `market` | article/correction/quote와 기사 ID·원문 버전 또는 종목·거래 시각/수정 버전의 고유 조합; 중복은 오류 |
| `published_at` | 출처 공개 시각; 미상은 null; 포털·최초 관측으로 대체하지 않음 |
| `portal_display_at` | 포털이 표시한 시각; 공개 시각과 별개 |
| `observed_at` | 해당 버전을 수집기가 최초 확인한 시각; 재생 기사에서는 저장 호출 직전 로컬 관측 |
| `stored_at` | 저장 호출 반환 후 확인한 커밋 완료 시각의 상한; 내부 커밋 순간의 정밀 추적은 아님 |
| `processed_at` | 가공 저장 호출 반환 후 완료 확인 시각; 내부 제안의 가공 시작/생성 시각과 다름 |

시각에는 시간대가 필수다. 백분위는 nearest-rank로 계산하고 각 분포의 유효 표본 수와 대상 전체 분모를 함께 낸다. 음수나 미래 시각이 포함된 지연은 정상 분포에서 제외하고 건수로 남긴다. 결측 시각을 채우지 않으며 표본이 없으면 백분위도 null이다. 기사/정정의 모든 예산 대상에 유효한 표시 관측이 있어야 통과를 판정한다. 일부라도 미관측이면 통과를 보류한다. 이미 관측한 p95가 10초를 초과하면 미달이다.

브라우저를 관측하지 않은 저장 버전은 화면 미반영으로 확정하지 않는다. 반영률은 null, 미확인 건수와 확인된 하한만 제공한다. `independent_source_targets`가 없으면 누락률도 null이다. 대상이 있으면 정확한 버전 조합으로 대조하되 선언한 독립 확인 구간만 평가하고 전체 출처 회수율은 주장하지 않는다. 실제 사용 시 `source_scope`에 독립 확인한 기간·출처·목록의 범위와 근거 경로를 기록해야 한다.

`tracked_status`는 고유한 시장/종목/관측 시점마다 정상·지연·실패·누락·미지원·장외·거래 없음 상태를 받는다. `five_minute`는 시장/종목/UTC 분 경계를 고유 분모로 삼고 기존 `price_tracking.recent` 결과를 보존한다. `pending`은 비교 양 끝점 부족, `observation_gap`은 중간 공백 또는 정규장 상태 불일치, `stale`은 수집 지연·실패, `outside_session`은 5분 전체가 정규장 안에 있지 않음, `session_unverified`는 거래 일정 미확인이다. 비교 ETF와 개별 종목은 별도로 집계한다. 실제 조사에서 거래 없음·휴장·수집 실패를 구분할 근거가 없으면 해당 상태를 임의로 정상 또는 장애로 확정하지 말아야 한다.

`observation_windows`에는 시장, 날짜, opening/intraday/closing/outside 구간, 독립 확인한 `normal_open_day_verified`를 기록한다. 실제 관측 모드이며 시장별 3개 날짜 모두 네 구간을 갖춰야 기간 기준을 충족한다. 이는 입력 기록의 충족 여부이며 캘린더나 조사 근거를 자동 검증하는 기능은 아니다. 합성 기록으로 실제 개장일 기준을 통과시킬 수 없다.

## 복구 범위와 남은 검증

합성 제공처 TimeoutError 후 실패 상태와 재시도 대기를 확인하고, 사본 DB의 대기 시간을 풀어 빈 목록 성공 응답으로 정상 수집 상태 복구를 확인했다. 실제 제공처 누락 기사 복구나 대기 시간 경과를 측정한 것은 아니다. 가격 누락 응답은 오류로 남고 마지막 성공 가격을 보존하며 이후 정상 입력으로 갱신됐다. SQLite 재연결과 별도 Python 프로세스의 로컬 HTTP 응답에서 정정·저장 상태가 유지됐다. 새 프로세스의 상장 목록은 비어 있었으며, 고정 목록을 복원한 동일 프로세스에서 종목 조회 시도가 재개됐다. 실제 `server.main` 시작 시 상장 목록 내려받기·300초 재시도·운영 재시작 시간은 미검증이다.

재생 run-003은 새 프로세스가 읽은 시세 상태가 반드시 정상이어야 한다는 평가기 가정 때문에 종료 코드 1로 실패했다. 앞선 상장 목록 평가에서 의도적으로 빈 시세 응답을 넣어 마지막 상태가 오류가 된 것이 원인이었다. 제품을 바꾸지 않고 재시작 직전 상태 전체와 이후 상태를 대조하도록 평가기를 고쳤다. run-004, run-005와 최종 run-final은 통과했다. 중간 실행 기록도 비공개 디렉터리에 남겼다.
