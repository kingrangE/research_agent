# 실제 브라우저 조회 평가 (#24)

이 평가는 API 지연과 화면 표시 지연을 구분한다. 운영 서버에 부하를 주지 않고, 다섯 SQLite DB의 고정 사본과 실제 Chrome으로 시장 진입 → 테마 선택 → 관련 뉴스 → 종목 시세·장중 차트 → 전체 뉴스 검색·페이지 이동을 재생한다. 유효한 시장 후보가 없으면 해당 경로를 빈 자료 또는 선행 조건 부족으로 남기고 전체 뉴스 경로를 계속 측정한다. LLM·임베딩·토스 호출과 외부 소켓을 차단하며 수집 작업자를 시작하지 않는다. UI와 제품 서버 코드를 변경하지 않는다.

시장 진입은 기존 `/?market-preview=1` 화면을 사용한다. 실험 옵션을 연 로컬 브라우저의 측정이며 기본 홈 전환이나 배포를 수행하지 않는다.

## 실행

Python 3.11 이상, Node.js, Docker, 기존 Playwright 설치와 Chromium/Chrome이 필요하다. 저장소에 새 npm 의존성을 설치하지 않는다. `--playwright-module`에는 사용 중인 Playwright 패키지 경로를, `--chrome`에는 별도 평가용 Chrome 실행 파일 경로를 지정할 수 있다. 실행 중인 개인용 대시보드 컨테이너의 이미지와 데이터 볼륨을 조회하지만 원래 컨테이너를 재시작하거나 설정을 바꾸지 않는다. 백업은 네트워크 없는 별도 보조 컨테이너에서 CPU 1개·메모리 256MB 제한과 읽기 전용 원본 볼륨으로 수행하며, 쓰기는 이 실행의 출력 폴더에만 한다. 큰 DB의 지문은 파일 전체를 메모리에 올리지 않고 계산하고, 복사한 사본의 지문도 고정 입력과 대조한다.

```sh
python3 scripts/benchmark_browser.py \
  --source-container research_agent-dashboard-1 \
  --playwright-module /absolute/path/to/node_modules/playwright \
  --chrome '/absolute/path/to/chrome'
```

기본 출력은 권한을 제한한 `.data/validation/browser24/run-<고유값>/`이며 Git에서 제외된다. 같은 입력을 재사용할 때는 원래 실행의 `snapshot` 폴더를 지정한다. 다섯 DB의 SHA-256·테이블별 건수를 검사하고 새 실행의 작업 사본을 만든다. 가격 관측 기준 시각도 원래 `preflight.json`의 `as_of`와 같게 지정한다. `--output`은 기존 실행을 덮어쓰지 않는 새 폴더여야 한다.

```sh
python3 scripts/benchmark_browser.py \
  --snapshot .data/validation/browser24/run-<원래실행>/snapshot \
  --as-of '<원래 preflight.json의 as_of>' \
  --playwright-module /absolute/path/to/node_modules/playwright \
  --chrome '/absolute/path/to/chrome'
node --test tests/test_browser_benchmark.mjs
```

`--repetitions 1`은 자동화 연동 검사에만 사용한다. 기본 예열 표본 수는 기기·네트워크 조합마다 100회이며, 표본이 100개 미만이면 예산 통과를 판정하지 않는다. 예산 미달·유효 자료 부족은 평가 결과다. 여정 자동화나 실행 기반의 오류는 종료 코드 1로 구분한다. 실패한 실행의 원시 파일도 보존한다.

같은 재사용 명령에 `--stock-only`를 추가하면 별도 보조 시나리오를 실행한다. 전체 뉴스에서 ‘삼성전자’를 검색한 뒤 실제 기사에 연결된 `005930` 종목 버튼으로 상세와 차트를 연다. 시장 후보가 없어도 보관 차트를 확인할 수 있는 기존 UI 경로이며, 시장→테마 여정의 성공으로 합산하지 않는다. 재시작 첫 여정과 별도 예열 여정은 각각 상세를 한 번 열고 닫는다. 예열 측정은 기기·네트워크별로 준비된 브라우저 문맥 하나에서 같은 상세를 100회 열고 닫으며 매번 차트 API 요청과 실제 표시를 측정한다. 기본 시나리오의 매번 새 브라우저 여정과 캐시 조건이 다르므로 합치지 않는다. 기본 시장은 국내이며 미국 시장 전환, 실제 휴대기기와 물리 디스플레이 시각은 미검증이다.

브라우저 문맥과 HTTP 캐시는 매 여정 새로 만들며 서버 프로세스의 예열 여부와 구분한다. 메모리 전용 초기화 수단과 파생 캐시 없는 최초 계산 절차는 구현하지 않았으므로 두 상태는 미검증이다. OS 디스크 캐시는 비우지 않으며 재시작을 OS 콜드로 부르지 않는다. 등록 종목·관계 규칙과 DB 지문, 실제 HEAD, 코드 파일 지문, 장비·런타임·시각은 측정 전에 저장한다. 다섯 DB는 각각 일관된 SQLite 백업이지만 DB 사이를 묶는 단일 트랜잭션은 아니다. 가격 관측 기준 시각만 고정하고 브라우저의 벽시계는 실제 시각을 사용한다. 지속 시간은 단조 증가 시계로 측정한다.

네트워크와 CPU는 DevTools의 고정 설정이며 실제 회선 RTT나 휴대기기 CPU로 교정한 값은 아니다. API의 첫 바이트 시각은 브라우저 Resource Timing 기준이고 JavaScript의 응답 처리·렌더링 대기와 구분한다.

## 지표와 판정의 경계

각 단계는 클릭 이벤트 또는 탐색 시작부터 올바른 실제 자료의 DOM이 준비된 시각과 이후 두 번의 `requestAnimationFrame` 시각을 기록한다. `time_origin_ms`에 단계의 상대 시각을 더하면 요청의 `wall_time`과 연결할 수 있다. 이는 브라우저의 렌더링 기회에 대한 근사치이며 물리 디스플레이에 실제 픽셀이 표시된 시각을 증명하지 않는다. 화면에 보이는 자료만 성공으로 집계하며, 좁은 화면에서는 관련 뉴스와 차트를 실제로 스크롤해 확인한다. 로딩·실패 문구와 빈 결과는 정상 자료의 표시 시간에 넣지 않는다. 이 한계 때문에 물리적 첫 페인트 기준은 별도로 미검증이다.

관련 종목 코드와 뉴스 식별자를 API 응답과 대조하며, 관련 뉴스 최대 8건·전체 뉴스 30건·실제 차트 점 수를 남긴다. 8건을 확보하지 못한 경로는 8건 성능 검증을 통과한 것으로 해석하지 않는다. 저장 시세는 원래 시각과 보관 필드만 재생한다. 현재 추적 DB는 당일 등락률을 보관하지 않으므로 완전한 시세 응답의 재생 자료가 아니며, 시세 API의 HTTP 전송 지연을 측정해도 정상 시세 표시 성능의 통과로 판정할 수 없다. 종목 연결·가격·누락 필드를 합성하지 않는다. 시장 비교와 관련 뉴스는 현재 UI에서 시장 API와 대시보드 자료로 만들어지는 경로이므로 별도 API가 있는 것처럼 측정하지 않는다.

`preflight.json`은 입력·장비·사전 예산, `browser-plan.json`은 실제 브라우저 버전·네트워크 설정, `server-starts.jsonl`은 서버 초기화 비용, `raw.jsonl`은 모든 측정 여정의 단계·요청·바이트·장기 작업·중복 요청·자료 건수, `summary.json`은 기기·네트워크·캐시별 p50/p95/p99와 분모를 담는다. 분포는 nearest-rank 방식이며 성공 표본만으로 계산한다. 빈 자료·차단·실패·시간 초과·여정 종료 시 남은 요청을 별도로 남긴다. HTTP 200의 API 전송 성공과 화면에서 유효 자료를 표시한 성공은 서로 다른 판정이다. 각 조합의 첫 측정 여정에는 Playwright 추적 ZIP과 PNG를 추가하고 나머지 여정도 원시 시간 기록을 남긴다.

API 지연은 브라우저 Resource Timing의 요청 시작·첫 응답 바이트·응답 완료 시각으로 계산한다. 비동기 CDP 이벤트의 전달 시각은 진단용으로만 보존한다. 시간 순서나 요청 대응을 확인하지 못한 값은 0으로 채우거나 보정하지 않고 미계측으로 남기므로 HTTP 성공 수와 유효 시간 표본 수가 다를 수 있다. 마지막 측정 클릭 이후에만 주기 갱신을 멈추고 이미 시작된 요청의 완료 기록을 모은다. 측정 중 갱신·중복 요청을 제거하지 않는다. 오류·빈 자료의 시간 분포는 `by_status`에 따로 보존한다.

추적에는 기사·시세·화면 내용이 들어갈 수 있으므로 원시 JSONL·ZIP·PNG·SQLite를 공개하거나 커밋하지 않는다. 공개 가능한 결과는 집계와 재현 절차에 한정한다. 같은 호스트에서 다른 작업이 병행되므로 격리 성능이나 전후 개선 배수를 주장하지 않는다. 사람의 탐색 시간·이해도와 운영 전체 상장 목록도 이 평가의 결과가 아니다.

제품 코드 기준은 `f7b9190c5bba1166cba2166d4361f2cb0712ed86`이며 변경 전후 성능 개선 비교는 하지 않았다. macOS 26.3.1, Apple M2 Pro 12 논리 CPU, 메모리 16GiB, Python 3.13.2, SQLite 3.49.1, Node 23.10.0, Playwright 1.62.1, Chrome 152.0.7977.65에서 수집 작업자 없이 별도 서버 한 개로 측정했다. 공유 호스트의 자원 경쟁이 있어 격리 성능이 아니다. 모든 시세·뉴스는 고정 보관자료의 재생이며 실시간 공급자 응답 검증이 아니다.
