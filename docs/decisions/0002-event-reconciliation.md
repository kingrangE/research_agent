# 같은 제목 사건의 비파괴 연결 재검토

2026-11-15 시제품에서 채택했다. 목표는 두 원문을 모두 알게 된 이후에 중복 사건을 다시 검토하면서 원래 분석과 당시 시각을 보존하는 것이다. 발행 순서와 처리 순서가 달랐던 실제 포털·언론사 기사에서 기존 후보 검색만으로는 저장 중복이 해소되지 않았다.

원본 사건은 본문 읽기 단계가 저장한 사실과 원래 사건 ID다. 표시 사건은 연결 검토가 같은 사실이라고 판단한 원본 사건들을 현재 화면에서 함께 보여주는 단위다. 연결 결정은 사실을 다시 추출하거나 원본 사건을 수정하는 명령이 아니라, 특정 모델·정책·원문 스냅샷에 대한 별도 기록이다.

현재 화면의 발행 시각이 유효한 최근 기사 중 원제목이 정확히 같고 각각 기사 한 건인 두 원본 사건만 자동 비교한다. 미래 관측은 쓰지 않는다. 최초 보도가 오래됐어도 그 시각을 알고 있으면 비교할 수 있으며, 연결 후 최초 보도가 26시간을 넘으면 추천에서 제외한다. 세 사건 이상이거나 이미 복수 기사를 묶은 사건은 보류하고 수집 현황에 표시한다. 제목 일치는 후보 조건이며 동일 사건의 확정 근거가 아니다.

본문 읽기와 같은 로컬 모델이 원제목·발행일·공개 인용 두 묶음을 비교해 같은 경제적 사실인지 불리언만 반환한다. 당사자·행동·대상·발생 시점을 비교하고, 다른 계약·고객·실적 기간과 후속 취소·정정은 구분한다. 상태·당사자 검증은 두 방향으로 적용한다. 같은 정정 사실을 다시 보도한 경우는 연결할 수 있다. 모델의 새 요약이나 추천 설명은 생성하지 않으며 다른 모델·전문가의 독립 검수로 표현하지 않는다.

입력 사실·본문 버전·최초 발행·모델·본문 및 연결 기준으로 검토 키를 만든다. SQLite의 별도 연결 기록에는 입력 스냅샷·판단·검토 시각·정책과 모델 범위를 보존한다. 사실이나 기준이 달라지면 이전 기록을 현재 연결로 재사용하지 않는다. 유효한 부정 판단도 캐시하며 훼손된 기록은 승인으로 취급하지 않는다. 미확인·오류·대기 상태는 원본 분리를 유지한다. 같은 입력 실패는 60초 뒤 재시도하고 새 입력에는 실패 대기를 넘기지 않는다.

일반 분석 작업을 먼저 수행하며 무작업 회차나 기존 작업 순환 번호가 3의 배수인 회차에서 최대 한 쌍을 추가 검토한다. 같은 입력의 캐시 재사용에는 모델을 부르지 않는다. 이는 로컬 모델의 일일 호출 제한이 아니라 새 기사 처리와 연결 보충 사이의 순환 배분이다. 연결·정렬도 같은 작업자의 처리 시간을 쓰므로 전체 지연 개선을 보장하지 않는다.

화면에 묶을 때 최초 발행이 가장 이른 원본 사건의 ID를 기준으로 삼는다. 대표 원문의 기존 사실·분석 시각을 유지하고 기사마다 원래 사건 ID를 보존한다. 이력은 두 원본에서 합쳐 최근 최대 10건을 보여주되 원본 저장 행은 삭제·갱신하지 않는다. 연결 검토 시각을 새 본문 분석이나 새 발행 시각으로 바꾸지 않는다. 표시 묶음이 바뀌면 기존 원문·시장 지문이 맞는 순위만 재사용하며 필요한 순위는 다시 비교한다. 읽기·선별 기준과 과거 사실 캐시는 일괄 무효화하지 않는다.

기존 ID를 SQL로 일괄 바꾸는 대안은 원래 분석과 잘못된 연결의 복구 근거를 훼손한다. 전체 기사를 다시 추론하는 대안은 비용·대기와 새 사실 추출 오류를 늘린다. 제목만으로 병합하는 대안은 다른 거래를 섞을 수 있다. 벡터 검색·대규모 그래프 군집화는 표현이 다른 중복과 복잡한 묶음의 품질 검증 이후에 검토한다. 현재는 작은 비교와 독립 기록으로 기존 자료를 보존하는 경로를 먼저 선택했다.

코드를 되돌리면 별도 기록은 남고 원본 사건 표시로 복귀할 수 있다. 원문이나 정책이 달라져도 이전 결정을 이력으로 남기고 현재 화면에는 적용하지 않는다. 동일 입력에 대한 사람의 판단 수정과 세 사건 이상 재검토, 원제목이 다른 기사, 과거 전체 자료에 대한 연결은 아직 별도 기능이 없다. 원문 인용은 기사 주장의 진위·기업 노출·투자 성과를 검증한 자료가 아니며 잘못된 모델 연결 가능성이 남아 있다.
