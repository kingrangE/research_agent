# 뉴스 이후의 실측 시세 추적

## 문제와 목표

사용자는 뉴스가 나온 뒤 관련 종목이 지금 어떻게 움직이는지 확인하려 했다. 기존 버튼은 저장된 일봉 계산만 읽었으며, 지원하는 사건 축으로 분류되고 등록된 관측 종목이어야 작업이 생성됐다. 실제 엔비디아 관련 최신 기사도 사건 미분류로 저장 계산이 0건이었다. 작업자는 정상 실행 중이었으므로 작업자 재시작이나 빈 상태 문구 변경만으로 해결되지 않는다.

사건 추출과 독립적으로 관련 종목의 실제 관측 시세를 기록하고, 뉴스 상세의 기존 종목 영역에서 추적 시작 대비 변화율과 추이를 보여준다. 뉴스가 가격 변화를 일으켰다는 판정이나 매매 수익 계산은 아니다.

## 선택과 대안

- 기존 Npay 현재가 조회, 상장 목록 대조와 관련 종목 연결을 재사용한다. 일봉 완료를 기다리지 않고 관측한 현재가를 비교할 수 있으며 AI 호출이나 새 인증은 필요하지 않다.
- 일봉 작업의 사건 분류 조건만 풀면 장중 변화가 보이지 않는 문제는 남는다. 일봉 계산과 비교 가능한 과거 사건 조회는 상세 근거에 유지한다.
- 토스 분봉으로 기사 시각의 가격을 소급하는 방법은 봉 시각의 의미와 보관 범위를 충분히 검증하지 못해 이번에 사용하지 않았다. 시간외 시세나 과거 시세 권한이 확보됐다고 확대 해석하지 않는다.

## 관측과 표시 기준

- 기사 발행 시각, 포털 표시 시각, 최초 수집 시각, 조회 시작 시각을 구분한다. 해당 기준 시각 이후 실제로 보관한 첫 거래 시세가 비교의 시작점이다. 과거 기사도 실제 추적 시각을 표시하며 기사 당시 가격을 만들어 넣지 않는다.
- 첫 거래 시세만 있으면 추적 시작 상태이며 변화율을 내지 않는다. 서로 다른 거래 시각의 가격 두 개가 있어야 계산한다. 실제 같은 가격이 두 번 관측된 경우에만 0%가 가능하다.
- 동일 종목, 출처, 통화의 유효한 가격을 비교한다. 0원, 비유한 값, 시각에 시간대가 없는 값, 미래 시세, 실패 또는 오래된 조회값은 새 관측에 넣지 않는다. 기사 이전의 장 마감 가격은 기사 이후의 시작 가격으로 사용하지 않는다.
- 같은 거래 시각을 반복 조회한 것은 새 가격 표본으로 세지 않는다. 같은 시각의 가격 정정은 보존하고 표시에서는 최신 정정을 사용한다. 절대 변화율이 40%를 넘으면 주식 분할 등 확인 전 상태로 두며, 이 규칙이 모든 기업행동을 검출하는 것은 아니다.
- 그래프의 가로축은 실제 거래 시각 간격을 사용한다. 최신 최대 120개 거래 시각과 첫 관측을 보여주며 전체 틱이나 표본 사이 움직임을 보장하지 않는다. 시세 정보와 한계는 펼쳐보고, 기본 화면에는 종목, 변화율, 추이와 관측 기간을 둔다.

## 실행과 복구

- 대시보드의 별도 백그라운드 스레드가 최근 26시간 내 최신 60개 기사의 관련 종목을 등록한다. 과거 기사를 열면 해당 기사도 추적 대상으로 등록한다. 이 범위는 모든 기사 수집 범위를 줄이지 않는다.
- 한 회차에 최대 20개 종목을 마지막 요청 시각 순으로 조회하고 완료 후 10초 뒤 반복한다. 기존 10초 시세 캐시와 요청 풀을 공유한다. 활성 종목 수, 공급자 지연과 오류에 따라 간격이 늘어나므로 전 종목 10초 도착이나 실시간 틱을 보장하지 않는다.
- `price_tracking.sqlite3`를 기존 개인용 데이터 볼륨에 보관한다. 로컬 파일 잠금으로 추적 작업자의 중복 실행을 막고, 서버 재시작 뒤에도 첫 관측과 시세 이력을 유지한다. 여러 호스트 운영은 지원하지 않는다.
- 추적 등록과 마지막 조회 상태, 가격 표본을 SQLite 트랜잭션으로 저장한다. 공급자 요청 중에는 DB 잠금을 유지하지 않는다. 수집 실패는 이전 시세를 보존하고 마지막 조회 실패 또는 90초 초과를 갱신 지연으로 표시한다. 다음 회차에서 재시도한다.
- `/api/price-movement?article_id=...`는 실제 보관 기사를 대조한 뒤 추적을 등록하고 로컬 기록을 조회한다. 사용자가 임의 종목이나 가격을 주입할 수 없으며 HTTP 요청 자체에서 외부 시세를 수집하지 않는다. 브라우저는 상세가 열린 동안 5초마다 기록을 확인한다.
- 이전 기사의 늦은 응답은 현재 상세를 덮어쓰지 않는다. 갱신 중 펼침 상태와 종목 버튼 또는 설명의 포커스를 보존하고, 종목 상세가 열린 동안 배경 영역을 교체하지 않는다.

## 검증과 한계

실제 저장 계산이 없던 엔비디아 기사에서 추적 표본이 누적되고 변화율과 그래프가 갱신되는 것을 확인했다. 기사 표시 시각과 첫 추적 시각의 차이도 화면에서 확인했다. 데스크톱과 약 650px 화면에서 추이, 기준 설명 유지, 종목 상세 열기와 포커스 복귀를 확인했다. Python 349개와 UI 73개 검사가 통과했다.

개인용 Npay 공개 경로를 재사용하며 공식 틱 피드나 재배포 권한이 생긴 것은 아니다. 추적 기능 도입 전 가격, 미관측 구간, 시간외 거래와 기업행동 전체는 복원하지 않는다. 당시 체결 가능 가격, 거래 비용, 인과 효과, 전략 성과를 검증한 기능이 아니다. UI 변경이 실제 사용자 탐색 시간을 줄였는지도 별도 측정이 필요하다.
